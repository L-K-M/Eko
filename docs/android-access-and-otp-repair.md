# Android restricted settings, notification access, and OTP repair

## Why these steps exist

Eko is sideloaded. Android 13 and newer can block special access for sideloaded apps until the user
explicitly allows restricted settings. Separately, Android 15 and newer can replace OTP text with
**Sensitive notification content hidden** unless Eko has trusted-listener status.

Eko obtains trusted-listener status through at least one CompanionDeviceManager (CDM) association.
Android caches that trust when the notification listener binds, so creating or replacing an
association is not enough by itself: the listener must complete a supported unbind/rebind cycle.

## Allow restricted settings on Android 13+

Perform this only when Eko was sideloaded and notification access is disabled, unavailable, or does
not remain enabled.

1. Open Android **Settings > Apps > Eko**. You can also long-press Eko's launcher icon and choose
   **App info**.
2. Open the three-dot overflow menu in the top-right corner.
3. Choose **Allow restricted settings**.
4. Authenticate with the device PIN, pattern, password, or biometrics if requested.
5. Return to Eko and continue to notification access.

If the menu item is absent, Android may not classify this install as restricted, it may already be
allowed, or the OEM may place the action under an additional-security screen. Do not install a random
settings helper. Confirm that the APK came from the official release and use Eko's in-app link back to
App info.

Work-managed devices can prohibit this choice. Eko cannot override device policy.

## Enable notification access

1. In Eko, open **Setup** or **Health and Diagnostics**.
2. Choose **Notification access**. On Android 11 and newer Eko opens its own listener row when the OS
   supports that deep link; older releases open the full list.
3. Enable Eko and accept Android's disclosure.
4. Return to Eko and wait for **Access granted** and **Listener connected**. Access granted without a
   listener connection is not a healthy final state.
5. Send Eko's synthetic test notification and confirm it appears on the Mac.

Notification access allows Eko to read notification content and metadata, observe removals, and
dismiss clearable notifications when requested by the paired Mac. Eko v1 does not request SMS or
Accessibility access.

If Eko is installed in a managed work profile, stop and install it in the personal profile. Android
does not bind an in-profile notification listener. Work notifications seen by the personal listener
remain subject to administrator cross-profile policy.

## Check companion-device trust

Open **Eko > Health and Diagnostics** and inspect **Companion associations**.

- At least one non-revoked association for the current Android user is required for the primary OTP
  trust path.
- An association is independent of a Mac pairing. Do not delete it merely because its displayed
  device is the Wi-Fi router.
- A BLE association can also provide optional presence reliability on Android 16. A Wi-Fi access
  point association provides redaction trust but not BLE presence.
- Device Location Services must be on while the system association picker scans. No Eko location
  permission is needed.

Never create a `DEVICE_PROFILE_COMPUTER` or self-managed association as a workaround. Third-party
apps cannot obtain the required privileged permissions.

## Repair hidden OTP text

Use a synthetic OTP generated by a test app or service. Do not repeatedly request a real financial
code while troubleshooting.

1. Confirm **Notification access: granted** and **Listener: connected**.
2. Confirm at least one usable CDM association exists.
3. In Eko, choose **Run listener repair**.
4. Keep Eko open until diagnostics show `requestUnbind`, `listener disconnected`, `requestRebind`,
   and `listener connected` in that order. If the listener was already disconnected, `requestRebind`
   followed by `listener connected` is sufficient.
5. Send a new synthetic OTP notification. Updating an old notification may preserve text Android
   classified under the old listener state.
6. If redaction remains, revoke and recreate one association through Eko, then run repair again.
7. If the listener does not reconnect after its grace period, manually toggle Eko notification
   access off, wait ten seconds, turn it on, return to Eko, and retest.

Eko must never disable and re-enable its own service component as a repair mechanism. Only Android's
notification-access screen and the supported `requestUnbind`/`requestRebind` APIs are used.

## One-time adb fallback

Use this only when CDM plus rebind fails on a tested retail build. `adb` is a device-owner action and
the app-op remains an OS-level exception until reset, app data is cleared, or firmware changes it.

1. Install Android SDK Platform Tools from Google.
2. Enable Developer options and USB debugging on the phone.
3. Connect the phone, run `adb devices`, approve the host key on the phone, and confirm the device is
   listed as `device`, not `unauthorized`.
4. Confirm Eko's diagnostics reports the Android package ID `dev.eko.android`. Stop if the installed
   package reports a different ID; these commands must not be applied to another app.

On macOS or Linux:

```sh
EKO_PACKAGE='dev.eko.android'
adb shell appops set "$EKO_PACKAGE" RECEIVE_SENSITIVE_NOTIFICATIONS allow
adb shell appops get "$EKO_PACKAGE" RECEIVE_SENSITIVE_NOTIFICATIONS
```

On Windows PowerShell:

```powershell
$EkoPackage = 'dev.eko.android'
adb shell appops set $EkoPackage RECEIVE_SENSITIVE_NOTIFICATIONS allow
adb shell appops get $EkoPackage RECEIVE_SENSITIVE_NOTIFICATIONS
```

The query must report an allowed mode for `RECEIVE_SENSITIVE_NOTIFICATIONS`. Run listener repair and
send a fresh synthetic OTP. Turn USB debugging off when finished.

To return the app-op to platform default, reconnect the same phone and run:

```sh
adb shell appops set "$EKO_PACKAGE" RECEIVE_SENSITIVE_NOTIFICATIONS default
```

PowerShell uses `$EkoPackage` in place of `$EKO_PACKAGE`.

## Enhanced notifications fallback

As a last resort, Android's **Enhanced notifications** setting can be disabled. The exact path varies
by release and OEM; search Android Settings for that phrase, usually under **Notifications > Enhanced
notifications**.

This is system-wide. It can reduce notification suggestions, actions, ranking, and sensitive-content
classification for every app, not only Eko. Record the original setting, turn it off, run listener
repair, and test with a new synthetic OTP. Restore it when testing is complete unless the user accepts
the system-wide tradeoff.

## Other unhealthy states

| State | Meaning | Action |
|---|---|---|
| Access granted, listener disconnected | Android has not bound Eko or the listener died | Run listener repair; then use the manual access toggle if it exceeds the grace period |
| No associations | OTP trust is not established | Enable Location Services and create an association through Eko |
| Association created, OTP still hidden | Bind-time trust cache is stale or OEM behavior differs | Run unbind/rebind; then use the documented fallbacks |
| Writer overflow | Some callback inputs may not have committed | Export diagnostics; Eko should emit a suspected capture gap if it can commit the evidence |
| Task Manager Stop recorded | The user explicitly stopped the foreground service | Open Eko and choose Resume; do not expect a background restart loop |
| Settings force-stop | Android keeps the package stopped | Open Eko manually, choose Resume if shown, and retest |
| Notification silence only | No proof of listener failure | Send a controlled test notification and inspect listener/process evidence |

The normal Android notification runtime permission controls Eko's own foreground-service status and
repair alerts. Denying it does not by itself revoke notification-listener access or prevent the
connected-device foreground service from starting.
